How · 方案架构

一条自动化的解析链路

小程序端捕获剪贴板，云函数调用 DeepSeek 完成结构化解析，落库后通过微信订阅消息实现到点提醒。

技术栈：微信小程序（WXML/WXSS/JS）· 微信云开发（云函数 + 云数据库）· DeepSeek deepseek-chat（temperature=0，JSON 模式）· 微信订阅消息。 个人主体小程序，类目"工具-效率"；系统日历写入经真机验证不可用，故采用"小程序内日程 + 订阅消息提醒"方案。

Tech · 技术亮点

Dev Log · AI 协作开发

给 AI 系统做工程化度量

本项目以"评测闭环驱动"的方式迭代：先有确定性评测（固定切分 + 相对时间锚点 + 五层指标），再以 badcase 反向改 prompt，每一步都用数字验收。

  • 建评测闭环：100 条语料 + 8:2 固定切分（种子 20260717），五层指标覆盖 has_schedule 判定 / 误报率 / 事件级 P·R / 字段准确率 / 端到端正确率。产出：run_eval.py + corpus/sample.jsonl + gen_corpus.py
  • prompt v1 → v1.2：badcase 驱动，新增时段映射、相对星期未来向、行动意图必提取等规则。结果：端到端 66.2% → 70.0% → 75.0%（dev/test 双达标）
  • 前端体验优化：剪贴板 30 字预览防撑爆布局；确认页日期/时间改用原生 picker。并清理未引用的 event-card 组件与 format.js 死代码
  • 工程化收尾：密钥走本地 .env（不进对话/不进仓库）；一键评测启动器 run_dev.sh/.bat；git 初始化并修复沙箱回滚导致的工作树事故。HEAD = bdc07c4
