Game Radar｜中美日韩 App Store 免费游戏榜追踪

每 12 小时抓一次美国、中国、日本、韩国的免费游戏榜 Top 100，把「第一次进榜」的产品存成可回看的台账，产出三页静态站和一份可逐条复算的分析。在线版是最近一次本地构建的快照，不是实时榜单。

数据面板 截至 2026-11-09，连续 18 个榜日、缺日 0

可运行 18 个榜日 · 7,200 条榜位 缺日 0 纯标准库 Python 3.10+ SQL · 7 个分析查询

01

解决什么

Apple 只提供当前榜快照，没有历史接口。想回看「某天有哪些新面孔、后来还在不在榜」，只能自己把每天的数据存下来。

榜单不解释玩法

只给产品名和名次。

四国商店介绍多语种

日、韩、英、中文，中文读者看不懂相当一部分。

逐个点商店页补不齐

能补信息，但没法按天回看，也没法和其他市场并排比。

台账里同时列：当天／当周第一次进榜的产品，每个产品的玩法一句话、玩法类型、中文译名、品类和上架天数，以及上一榜日进来的产品现在还在不在榜。

02

数据与技术

采集到建页是本地跑的一条链，不依赖后端服务。

项口径
来源Apple RSS topfreeapplications（genre=6014 为 Games 顶级类）+ lookup 详情
范围四国 × 免费游戏榜 Top100 × 每 12 小时一次
面板截至 2026-11-09，连续 18 个榜日（10-23→11-09），7,200 条榜位、缺日 0；窗口内 514 个产品、672 条「产品 × 店面」
存储fact_rank 榜位、fact_metric 评分快照、dim_app / dim_app_country 产品与店面、fact_tag 标签、job_log 抓取记录

模型只用在三处

玩法一句话（≤40 字）、玩法类型短语（≤12 字，如「三消+家装」「水排序」）、中文译名；日韩介绍另有单独译文脚本。生成结果带 descr_country / descr_sha1 记录依据的是哪国、哪份描述；同一份描述不重复生成，人工标签不被覆盖，写不出就留空。

Python；SQLite（WAL）；deepseek-chat 可选（没有 key 时台账、页面、分析照常生成，只是卡片缺玩法与译名）；三页静态站样式脚本内联，无运行时服务。

03

三页产出

三页各自是完整的一屏，双击就能打开，页面之间互相链接。

当日榜

首次进榜 / 上次进榜产品的名次变化 / 当前榜单构成（上架时长分布、品类席位前 5）。

前一榜日

同一套结构，按该榜日截点重算。

周报

最近一个 7 榜日齐全的已结束自然周：本周首次进榜、进榜名次分布、与上周对照、口径。

每张卡常显玩法一句话、玩法类型、中文译名、品类、上架天数、厂商与进榜名次；展开可看商店介绍预览（前 320 字，末尾回链 App Store 看全文）、日韩介绍的中文译文和首张截图。日报各组默认展开；周报只展开「新上架（≤30 天）」，并按首次进榜市场再分四段；周报按产品去重，同一款跨多国进榜只列一次。

05

口径与局限

台账里的每个数字都能用一条 SQL 重算。

口径

「首次进榜」怎么定义

产品在可观测窗口内第一次出现在该市场 Top100；面板起点那天已经在榜的按左删失排除，不计入首次进榜。

局限
  • 只有免费榜 Top100，榜外新品不可见。
  • Apple 不公开榜单算法，名次是结果不是原因，不能反推下载量、收入或用户规模。
  • 单日数据无法回补，因此每 12 小时抓一次、一天两班互为冗余。
  • 品类来自 Apple sub_genre，与「玩法」不是一套粒度，两者不能平移比较；Unclassified 是上游缺失，不是零。
  • 玩法、类型、译名、译文由模型依据商店介绍生成，介绍含糊时输出也含糊或留空。
  • 累计评价份额与品类集中度（前四名占比）是存档数字，依赖会被后续抓取覆盖的字段，不参与可复现校验。
06

SQL 片段

01

判断「真新进榜」时先把老产品剔掉

面板第一天就在榜的产品不算新进榜——它们是左删失，得先排除，否则一开榜就把整批老产品报成新面孔。
-- 连续段编号：同一段内 (日期序数 - 行号) 恒定，换段即变 CAST(julianday(snap_date) AS INTEGER) - rn AS island_id ... COUNT(*) OVER (PARTITION BY country, chart, app_id, island_id) AS streak_days, CASE WHEN prev_rank IS NULL THEN 1 ELSE 0 END AS is_new_entry, CASE WHEN prev_rank IS NOT NULL AND gap_days > 1 THEN 1 ELSE 0 END AS is_reentry, CASE WHEN first_seen = (SELECT MIN(snap_date) FROM fact_rank) THEN 1 ELSE 0 END AS is_censored,

真新进榜 = is_new_entry = 1 且 is_censored = 0。连续在榜天数用 gaps-and-islands 算，掉榜一次即重算；断档后回来的产品另记为 is_reentry，不并进新游。

02

同一个「留榜」为什么有两个百分比

「第 7 天还在榜」和「连续 7 天都在榜」是两件事。前者会掉榜后又回来、非单调；后者掉了就断了，才能画成衰减曲线。两种都算，是因为前者常被误当成留存。
SELECT 'fixed7' AS basis, k AS days_since_entry, SUM(observable) AS n_at_risk, SUM(observable AND still_continuous) AS n_continuous, ROUND(1.0 * SUM(observable AND still_continuous) / NULLIF(SUM(observable), 0), 3) AS p_continuous, SUM(observable AND in_rank) AS n_point, ROUND(1.0 * SUM(observable AND in_rank) / NULLIF(SUM(observable), 0), 3) AS p_point, SUM(observable AND in_rank AND NOT still_continuous) AS n_back, SUM(NOT observable) AS n_censored FROM calc WHERE in_fixed7 AND k <= 7 GROUP BY k

fixed7 只取「进榜后至少能观察 7 天」的那批，k=1..7 共用同一个分母。p_continuous 是连续在榜（画曲线用），p_point 是第 k 天当天在榜，n_back 是中间掉过榜又回来的条数——对应结果表里的 23.8% / 48.3% / 35 条。

两段均摘自仓库 sql/02_rank_moves.sql 与 sql/07_cohort_survival.sql；七个查询各自对应报告里的一个数字口径，完整 SQL 与断言见源码。
